Sequência de páginas do host

Mapa para análise antes de implementar no Go. Cada item abre a tela com dados fictícios.

Regras desta versão

Senha do admin ≠ senha do aplicativo
O login desta pasta é só do admin. Cada celular tem usuário próprio, identificado pelo e-mail. O admin não usa a senha do aplicativo para entrar aqui.
Host só visualiza operação
O admin vê clientes, lançamentos e saldos dos usuários liberados. Não registra venda nem pagamento. Isso continua só no aparelho.
Perda de senha do aplicativo
Na administração, o admin redefine a senha daquele e-mail para 000000. O celular abre o cadastro. Não altera a senha do admin.
Usuário nasce bloqueado
Após o pareamento, o e-mail fica aguardando liberação. Sync só depois da ação manual nesta página de administração.
Relatórios em dois cortes
Gerais (todos os celulares liberados) e por celular.

Ordem das telas

  1. 01 · Login do admin
    Senha do admin. Distinta da senha de cada usuário do aplicativo.
  2. 02 · Início
    Código de pareamento, atalhos e aparelhos aguardando liberação.
  3. 03 · Produtos
    Catálogo local e recebido dos celulares. Cadastro no host continua permitido.
  4. 04 · Novo produto
    Formulário de catálogo (não é lançamento de venda).
  5. 05 · Clientes
    Todos os celulares. Somente leitura. Coluna indica o aparelho de origem.
  6. 06 · Ficha do cliente
    Saldo e histórico. Sem botão de lançar ou abater.
  7. 07 · Relatórios gerais
    Totais e rankings de todos os celulares liberados.
  8. 08 · Relatórios por celular
    O mesmo conjunto de métricas, filtrado por aparelho.
  9. 09 · Administração de usuários
    Lista por e-mail, sem liberação por padrão, liberar, bloquear, redefinir senha.
  10. 10 · Confirmar reset de senha
    A senha daquele celular volta para 000000. A senha do host não muda.
